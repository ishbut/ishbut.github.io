# 网站维护指南

本指南面向接手维护本网站的学弟/学妹。目标是：**不用问人，也能独立完成日常改内容与上线**。

---

## 1. 网站是什么

- **性质**：纯静态英文网站（没有后端、没有数据库），用 Vite 构建，托管在 GitHub Pages。
- **线上地址**：https://ishbut.github.io/
- **内容源**：`src/content.mjs`、`src/recent-work.mjs`
- **页面生成器**：`scripts/generate.mjs`（把内容拼成根目录的 HTML）
- **生产仓库（唯一部署目标）**：https://github.com/ishbut/ishbut.github.io 的 `main` 分支
- **当前对外栏目**：Home / Members / Publications / Conferences / Access（Research、Awards、Patents 已从导航隐藏，页面文件仍保留、仍可访问）

> 所有面向访客的文字**必须是英文**。沟通用中文，但落到页面上一律英文。

## 2. 本地开发

```bash
cd ishbut
npm install          # 首次或依赖有变动时执行
npm run dev          # 本地预览：http://localhost:5173/
npm run build        # 手动构建到 dist/（本地日常改内容不需要，见下）
npm run preview      # 预览构建产物
```

**日常改内容不用敲任何命令**：项目根目录有 `start-local.command`，双击即可启动本地服务；开着服务时改 `src/` 下的源码，浏览器会自动刷新（见下）。部署也不用手动 build，线上的 Actions 会自动构建。

要点：

- `dev` 和 `build` 都会**先运行生成器**。而且 `vite.config.js` 里加了一个小插件：本地开着 `npm run dev` 时，修改 `src/content.mjs`、`src/recent-work.mjs` 或 `scripts/generate.mjs` 会**自动重新生成 HTML 并刷新浏览器**，不用手动重启服务或跑构建。
- 例外：往 `public/assets/` 里**新增**图片文件时，Vite 不会热加载新文件，需要**重启一次 dev server**（关掉终端重新双击 `start-local.command`）才能显示。给文件命名时一律用小写英文名并用连字符（如 `yunxiao-mu.jpg`），不要用大写，否则本地/线上大小写不一致会导致图片加载失败。
- 线上部署本来就是全自动的（见第 5 节）。
- 根目录的 `index.html`、`teaching/index.html` 等是**生成物**，不要手工编辑，改源头（`src/content.mjs`）。
- `dist/` 不提交到 git。

## 4. 日常维护操作

### 4.1 改导航栏目

编辑 `src/content.mjs` 顶部的 `navigation` 数组：

```js
export const navigation = [
  ['Home', '/'],
  ['Members', '/teaching/'],
  ['Publications', '/publication/'],
  ['Conferences', '/conference/'],
  ['Access', '/services/']
];
```

**隐藏某个栏目但保留页面**：从 `navigation` 中删掉该项，同时到 `scripts/generate.mjs` 的 `pages` 里给对应页面加 `label`（用于生成 `<title>`，否则会报错）。目前 `Research`、`Awards`、`Patents` 就是这样处理的：

```js
'/research/': { content: research, label: 'Research' },
'/awards/':   { content: awards,   label: 'Awards' },
```

### 4.2 改首页

首页内容在 `src/content.mjs` 的 `home` 常量里，当前结构是：

1. **关键词云**：`<section class="keyword-banner">` 里的一堆 `<span class="kw-*">`，`kw-xl/lg/md/sm` 控制字号。缩写要写全（如 `ARTIFICIAL INTELLIGENCE SECURITY`，不要写 `AI SECURITY`）。
2. **居中标语**：`<p class="portal-tagline">`，目前只有大字 `Institute of Cyberspace Security`（首页门面，不要再往里加学校名/研究方向那串小字）。
3. **Highlights**：`${recentHighlights}`（由 `recentHighlights` 常量生成，见 4.3）。

注意：首页和大个人页共用 `recentHighlights`，但分别把标题替换成了 `Highlights`（首页在 `home` 里替换，个人页在 `memberPage()` 里替换）。

### 4.3 改 Highlights（首页 + 张明武个人页）

`src/content.mjs` 的 `recentHighlights` 常量，当前只放 5 条最新成果，每条**三行**：

```html
<li>
  <div class="highlight-title">论文标题（加粗）</div>
  <div class="highlight-authors">Y. Zhou, M. Zhang（作者缩写）</div>
  <div class="highlight-venue"><em>期刊名</em>, 2026</div>
</li>
```

新增/替换条目时保持这个三行结构，作者用首字母 + 姓（`Mingwu Zhang` → `M. Zhang`）。

### 4.4 改老师信息

`src/content.mjs` 的 `members` 数组，每位老师一个对象。常用字段：

| 字段 | 说明 |
|---|---|
| `slug` | 决定个人页 URL，如 `mingwu` → `/teaching/mingwu/` |
| `name` / `role` | 卡片上的姓名和职位，如 `Professor • Ph.D.` |
| `photo` | 照片路径，必须放 `public/assets/teachers/` 下，写成 `/assets/teachers/xxx.png` |
| `summary` | Members 页"组长横排卡片"里的简介（张明武专属） |
| `leader: true` | 只有张明武有，让他独占一行 |
| `detail` | 指向 `profile` 常量，表示有完整个人页 |
| `contact` | 邮箱，会显示在个人页侧栏 |
| `placeholder: true` | 尚未完善资料的占位条目（目前 Yuzhu Wang、Yu Chen 仍是占位，但已有照片） |

**注意**：`summary`（Members 卡片简介）和 `profile` 里的简介（个人页正文）是两处独立文字，**改一处要同步改另一处**，否则两边不一致。

`memberTags` 对象控制卡片上显示的研究方向标签，每人最多两个，键 = `slug`。

新增一位老师：往 `members` 里加对象 → 放照片（重启一次 dev server）→ Members 卡片和个人页会自动生成（个人页路由由 `memberPaths` 自动推导）。确认无误后按第 5 节推送即可，线上会自动构建。

### 4.5 改学生信息

`src/content.mjs` 的 `currentStudents` 数组，字段：

| 字段 | 说明 |
|---|---|
| `name` / `degree` | 姓名；`"Master's"` 或 `'Ph.D.'` |
| `since` | 入学年份，如 `'2026'`；与学位合并在一行显示，如 `Master, 2026 –` / `PhD Candidate, 2025 –` |
| `link` | 可选，姓名变外链（目前 Kewen Wang 链到 GitHub） |
| `avatar` | 可选，头像路径，放 `public/assets/students/` 下 |

排序规则在 `currentStudentsBlock()` 里：**博士生优先 → 再按入学年份 → 同年级按姓名**。没照片的用姓名首字母占位圆。

### 4.6 改论文（Publications）

数据全部在 `src/recent-work.mjs`：

- `recentPapers`：正式发表的论文
- `preprints`：Online / Accepted / 预印本
- 每条是数组：`[年份, 作者, 标题, 期刊会议, 卷期页码, URL, 备注]`

页面当前**只显示 2026 年**（`papersPage()` 里用 `filter(p => p[0] === 2026)`）；Online/Accepted 那组标题显示为 `2027`（`renderYears(preprints2026, '', '2027')`），只是显示层改了，数据年份仍是 2026。

排版在 `renderPaper()`：**三行**（标题、作者、期刊+年份+备注），标题**不加链接**，作者统一缩写为首字母 + 姓（`abbreviateAuthors()` 自动处理）。备注里**不要写** CCF/JCR/中科院分区之类的内容，国外站点不放这些。

### 4.7 改 Conferences 页（承办会议）

目前是**承办会议**展示，数据集中在 `src/content.mjs` 的 `HOSTED_CONFERENCE` 常量里（名称、slug、全称、主办方、地点、年份都改这里）。

- 列表页 `conferencePage()`：一张可点击卡片（有详情）+ 一张不可点击的占位卡片（`is-static`），两张左右并排。占位卡片目前叫 `ICICS 2026`，只是名字占位，没有详情页。
- 详情页 `conferenceDetail()`：轮播三屏 + Welcome + Organizing Committee + Key Dates + News & Updates，文案是承办方视角。路径由 `slug` 决定（如 `css-2026` → `/conference/css-2026/`）。
- 想加第二个可点击的会议：把 `HOSTED_CONFERENCE` 改成数组并相应改造 `conferencePage()` / `conferencePages()`，再放一张卡片指向新 slug。

改 slug 会改变 URL，旧的生成目录要删掉（否则 `rsync --delete` 同步时会残留旧页面）。

### 4.8 改 Access 页

`src/content.mjs` 的 `services` 常量：顶部地址/联系信息 + 下方左右两个地图 iframe（左 Google，右**高德 Amap**，都定位湖北工业大学）。高德用的是免 Key 嵌入（POI ID + GCJ-02 坐标），没有推广广告。地址信息不要随意改。

### 4.9 改页头 / 页脚

`scripts/generate.mjs` 的 HTML 模板：

- 页头：校徽 + 两行文字（`HUBEI UNIVERSITY OF TECHNOLOGY` / `Institute of Cyberspace Security`），导航已收紧间距
- 页脚：一行版权 + 机构 + 学校名
- 右下角返回顶部按钮用的 Lucide `arrow-up` 图标

改这里会**影响所有页面**。

### 4.10 图标（Lucide）

站内图标统一用 [Lucide](https://lucide.dev/)，已作为 npm 依赖安装。

- 在 `src/main.js` 顶部 `import` 需要的图标，并加入 `createIcons({ icons: {...} })`。
- 在 HTML 里写占位：`<i data-lucide="arrow-up" aria-hidden="true"></i>`，脚本会替换成 SVG。
- 目前用到：`arrow-up`（返回顶部）、`map-pin` / `mail`（联系信息）、`arrow-up-right`（外链）、`arrow-right`（"See recent publications"）、`arrow-left`（详情页返回）、`chevron-left` / `chevron-right`（会议轮播箭头）。
- **不要再用 Unicode 字符**（`⌖`、`✉`、`↗`）当图标。

### 4.11 图片资源

- 老师照片、CV → `public/assets/teachers/`
- 学生头像 → `public/assets/students/`
- 校徽、关键词背景（`research-keywords-bg.webp`）、字体 → 留在 `public/assets/` 根目录

引用时用绝对路径 `/assets/teachers/xxx.jpg`，生成器会自动转成适合子目录的相对路径。

**命名铁律**：所有新图片文件名用小写英文 + 连字符（如 `cunzhi-li.jpg`），不要用大写。macOS 磁盘不区分大小写看着没问题，但 Vite / 线上 Linux 区分，大小写不对会导致图片加载失败。新增图片后需重启一次 dev server。

## 5. 部署（最重要，务必按顺序）

### 5.1 只有一个正确的部署目标

- ✅ **唯一可推送的仓库**：`https://github.com/ishbut/ishbut.github.io`（生产仓库）
- ❌ **绝对不要推送**：`https://github.com/Wcowin/ishbut`

原因：本地 git 的 `origin` 指向的是 `Wcowin/ishbut`（源码镜像），它**没有启用 GitHub Pages**，推了会触发失败的 Actions（红叉）。**不要执行 `git push origin`**。

### 5.2 标准推送流程

```bash
# 1. 本地提交（在本地工作目录 /Users/wangkewen/ishbut 执行）
cd /Users/wangkewen/ishbut
git add -A -- . ':(exclude)temp.md'
git commit -m "Short English summary of the changes"

# 2. 同步到生产仓库
rm -rf /tmp/ishbut-live-deploy
git clone --depth 1 https://github.com/ishbut/ishbut.github.io.git /tmp/ishbut-live-deploy
rsync -a --delete --exclude '.git/' --exclude 'temp.md' /Users/wangkewen/ishbut/ /tmp/ishbut-live-deploy/

# 3. 在生产仓库副本里提交并推送
cd /tmp/ishbut-live-deploy
git add -A
git commit -m "Short English summary of the changes"
git push origin main

# 4. 等 GitHub Actions 跑完并验证
gh run list -R ishbut/ishbut.github.io --limit 1
curl -s -o /dev/null -w "%{http_code}\n" https://ishbut.github.io/

# 5. 清理临时目录
rm -rf /tmp/ishbut-live-deploy
```

注意：

- `rsync` 的 `--delete` 会删除生产仓库里本地已没有的文件（比如改名后的旧页面），这是**期望行为**。
- **不要排除 `.github/`**：生产仓库的 Pages 工作流依赖它。
- **要排除 `temp.md`**：那只是几行参考链接的临时笔记，从不进提交（上面的 `git add` 和 `rsync` 都已排除）。
- **commit message 一律用英文**，简要写清本次改了什么（如 `Add student avatars and improve mobile layout`），不要只写 `update`，也不要写中文。

### 5.3 自动部署

生产仓库的 `.github/workflows/pages.yml` 在每次 push 到 `main` 后自动执行 `npm ci` → `npm run build` → 部署 `dist/` → 等待 30 秒 → 运行 `scripts/indexnow.mjs` 把 `sitemap.xml` 里的全部 URL 提交给 IndexNow 和 Bing，加快搜索引擎收录。通常 1 分钟内完成。

`sitemap.xml` 由 `generate.mjs` 每次构建时自动生成（列出全部页面），不用手动维护。`public/robots.txt` 声明了 sitemap 地址，`public/<32位key>.txt` 是 IndexNow 的域名校验文件——这两个文件不要删。

需要立刻通知搜索引擎时，也可在本地手动跑：`node scripts/indexnow.mjs`（需先 `npm run build` 生成 sitemap）。

如果 Actions 失败：先在 Actions 页面看日志；常见原因是构建报错（改错了 `src/` 里的代码）或 Pages 没配置成 GitHub Actions 来源。IndexNow 提交那步失败不影响网站本身。

## 7. 常见问题

**Q：改了内容但页面没变？**
A：确认改的是 `src/content.mjs` 而不是生成的 HTML。开着 `npm run dev` 时应该会自动重新生成并刷新；如果没刷新，看终端有没有 `[auto-generate]` 日志，或手动跑一次 `npm run build` 再强刷浏览器（Cmd+Shift+R）。

**Q：新增的学生头像不显示，卡片还是字母占位圆？**
A：两个常见原因：① 文件名用了大写（如 `Cunzhi-Li.jpg`），改成全小写 + 连字符（`cunzhi-li.jpg`）并与代码里的路径一致；② 往 `public/assets/` 新增文件后 Vite 不会热加载，需重启 dev server（关掉终端重新双击 `start-local.command`）。可用 `curl -I http://localhost:5173/assets/students/xxx.jpg` 检查，正确的 `Content-Type` 应是 `image/jpeg`，若是 `text/html` 说明文件没被识别。

**Q：本地页面正常，但样式在子页面（如 `/teaching/mingwu/`）丢了？**
A：检查资源路径写法。生成器只重写 HTML 里的 `/assets/...`，CSS 里的 `url('/assets/...')` 要保持绝对路径写法。

**Q：新增的成员页 404？**
A：`slug` 里不要有空格或中文；确认 `npm run build` 后 `teaching/<slug>/index.html` 生成了。

**Q：旧页面还在怎么办？**
A：`rsync --delete` 会清理生产仓库里本地已删除的页面；本地生成前也应删掉旧目录（如改名 slug 时）。

**Q：想恢复成更早期的版本？**
A：用 `git log` 找提交，在生产仓库里回滚并推送。本地源码仓库只做记录，部署以生产仓库为准。
